# test-driven-development：接入与实验结果

用同一行为测试先确认预期断言失败，再验证修复。 Skill 正文沿用实验中的简短适配版，附来源与 MIT 许可。

## 接入方式

1. 在项目角色设置中创建控制台文件 Skill bundle，加入 `test-driven-development/SKILL.md`；复现双 Skill 时把 `systematic-debugging/SKILL.md` 也放进同一包，并绑定给 Dev。也可将文件放入目标项目的 `.agents/skills/<名称>/SKILL.md`，刷新项目规则、固定提交和路径，再绑定。见[角色配置](../role-pool.md)。
2. 常规使用可让 Dev 按需读取。要复现实验，在 Dev 的 `persona_prompt` 末尾追加：「每次开发委派开始时，在调查或编辑前，用 `read_skill` 按路径读取绑定的 `SKILL.md` 正文并遵循其指引。」双 Skill 配置要指定两条路径；按包里实际显示的路径填写。
3. 启动新任务，检查 Dev 的 `skill_read` 日志是否记录了相应文件。只看到文件列表表示技能可用。合入本 PR 只提供技能文件，现有 Bot 运行时代码无需修改。

## 历史单 TDD 对照

| 指标 | Base | 单 TDD |

**单 TDD 组首次自主交付，Base 人工恢复后同分。** 首次累计时间和请求止于 Base 待重规划停点，不能用来衡量最终交付总成本。
